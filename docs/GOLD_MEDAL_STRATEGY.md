## 3. ゴールドメダル獲得のための 5 大技術ピラー（Detailed Engineering Specs）

### ピラー ①：【即効・主軸】ADK 14,336-Token Compaction 崖の完全封鎖とトークン収支設計

#### なぜコンパクションを避けるだけで解決率が 1.8 倍になるのか？
* Google ADK の `EventsCompactionConfig(token_threshold=14336, event_retention_size=5)` は、累積トークンが 14,336 を超えると、直近 5 件以外の会話履歴を要約文に縮約します。
* **要約の弊害**: 問題文の具体的な仕様文字列や、初期に `git grep` で見つけた正確なファイルパス・行番号が消滅します。結果としてモデルは同じファイルを再読み込み（read 呼び出しが 5.55 ➔ 8.68 へ +56.4% 激増）し、制限時間・ツール数を食い潰します。
* 実証データ: コンパクション 0 回の解決率は **47.7%**、1 回で **26.4%**、2 回で **7.1%**。

#### 厳密なトークン収支設計（Token Budget Balance Sheet）
コンパクション閾値（14,336 トークン）に対し、20 ターンのセッションで安全マージン（約 2,500 トークン）を確保する厳格なトークン配分です：

### ピラー ②：【即効】Grader-First 原則とテスト環境障害への耐性設計

#### スコアラー環境の「見かけの Red」トラップ
* 公式評価環境が `pytest -p no:anyio` を強制適用しているため、`starlette` や `requests` など外部プラグインや非同期 fixture に依存するテストは、**正しい正解コードを適用してもローカルでエラー（`fixture 'anyio_backend' not found` 等）を返します**（Topic 751707）。
* エージェントがこのエラーを見て「自分のパッチが間違っていた」と判断し、修正を取り消してしまう行動（自己破壊）が大量の 0 点タスクを生んでいました。

#### V11 での確定ルール（Grader-First Invariant）
1. **隠れ採点環境（Hidden Grader）の独立性**:
   * 採点者は提出された `git diff` をまっさらな新鮮コンテナに適用し、独自のテストハーネスで採点する。
   * **ローカルでのテストがプラグイン・fixture 要因で Red であっても、ソース差分が仕様を満たしていれば満点となる**。
2. **巻き戻し禁止指令**:
   * 「ローカルテストのエラーメッセージが、自分が編集したロジックの assertion ではなく、環境・インポート・fixture 起因である場合は完全に無視し、ソース修正を保持したまま `submit_patch` を呼ぶ」。

### ピラー ③：【即効】サンプリング多様性ポートフォリオ（Idris メソッド）

#### なぜ Temperature 1.0 が SWE ベンチマークで機能するのか？
* コード生成における一般的な常識（「コードは低温度 0.0〜0.2 が良い」）は、単純な関数生成タスクでのみ成立します。
* SWE-bench / SWE-Gemma のようなリポジトリレベルのデバッグでは、エージェントは **「探索空間の局所解（Local Minima）」** に囚われやすい特性があります。
  * 例: `edit_file` の `old_string` のインデントや改行が 1 箇所ズレている場合、`temp=0.2` では全く同じ間違った置換文字列を 2 度 3 度と繰り返し生成し、ツール予算を使い果たして自滅します。
  * `temperature: 1.0` + `top_k: 64` では、トークンの確率分布の適度なゆらぎにより、1 回失敗した次のターンで「別の行からマッチングを試みる」「Python インライン置換に切り替える」といった別経路の探索行動が自然に発現します。
* これが、世界 3 位の Muhammad Idris 氏がプロンプトやモデルを一切変えずに **0.18 ➔ 0.24 への 3 問ジャンプ** を実現した本質的メカニズムです。

### ピラー ④：FastAPI (55.5%) ＆ Rich (39.5%) の 2 大リポジトリ攻略

可解タスク 119 問の **95.0%（113 問）** は `fastapi` と `rich` の 2 つのリポジトリで占められています。
この 2 つのコードベース特有の不変条件（Invariants）をプロンプトおよび探索手順に反映します。

#### 1. `fastapi/fastapi` の典型 3 大パターンと攻略法
1. **Dependency Injection & Coroutine Handling (`fastapi/dependencies/utils.py`)**:
   * バグの型: `run_endpoint_function` や `solve_dependencies` で同期関数（`def`）と非同期関数（`async def`）の扱いが不揃い。
   * 攻略ルール: `is_coroutine_callable(dependant.call)` の判定、`anyio.to_thread.run_sync` と `await` の両系統を必ずペアで修正。
2. **Parameter Definition vs Runtime Consumer (`params.py` ➔ `routing.py`)**:
   * バグの型: `Query()`, `Path()`, `Header()` 等のパラメータクラスに新引数（例: `regex`, `alias`）が追加されたが、`routing.py` や `utils.py` の消費側で展開されていない。
   * 攻略ルール: 定義ファイル（`params.py`）を直したら、即座に消費側（`routing.py`）へ移動して同一引数を渡す。
3. **Docs Example Tasks (`docs_src/**`)**:
   * バグの型: ドキュメント修正タスクは本体ではなく `docs_src/` 配下のサンプルコードが採点対象。
   * 攻略ルール: Issue に「tutorial」や「documentation」の言及がある場合、検索対象を `docs_src/` に切り替える。

#### 2. `Textualize/rich` の典型 3 大パターンと攻略法
1. **Sentinel & None Boundary (`rich/console.py`, `rich/text.py`)**:
   * バグの型: `end=None` などの引数で、デフォルト値（改行 `\n`）と明示的な `None`（末尾文字なし）が同一視されてしまう。
   * 攻略ルール: `_NO_END = object()` などのモジュールレベルセンチネルを用いて区別する。
2. **Protocol & File Proxy (`rich/file_proxy.py`)**:
   * バグの型: `FileProxy` などのラッパークラスに標準ファイルオブジェクトのメソッド（`fileno()`, `isatty()` 等）が欠落。
   * 攻略ルール: 委譲（delegation）パターンで `getattr(self.file, name)` を実装するか、明示的なフォワードメソッドを追加。
3. **Traceback & Exception Chain (`rich/traceback.py`)**:
   * バグの型: 例外の `__cause__` や `__context__` の再帰的レンダリング時の循環参照やフォーマット欠損。
   * 攻略ルール: `seen` セットによる循環チェックと、Python 3.11 以上の新属性（`add_note` 等）への安全なアクセス。

### ピラー ⑤：【防衛】Private 評価（Shakeup）でのゴールド死守戦略

#### なぜ「非同期過学習」チームが Private で脱落するのか？
* ホスト公式発表（Topic 745998）:
  > *"None of the private repo tasks touch any functions defined with `async def`."*
* Public LB で上位にいるチームの中には、FastAPI/HTTPX の非同期タスクに特化させたプロンプト（`async def` の専用テンプレート等）を組んでいるケースが散見されます。
* しかし Private は **100% 同期コード（普通の Python クラス・関数・データ構造）** であるため、それらの特化ルールは無効化し、プロンプトの貴重な注意（Attention）を浪費してスコアが急落（Shakeup 転落）します。

#### 当チームの Private 耐性アーキテクチャ
* 非同期専用ルールは「もし parallel に存在すれば両方直す」という 2 行のルールに圧縮。
* プロンプトの主軸を **「境界値（None sentinel）、例外クラスの厳密一致、引数のデフォルト値、型オーバーロード」** という Python 言語全般の普遍的契約（Universal Contracts）に置くことで、Private リポジトリ（未公開の 35+ リポジトリ群）で確実に高得点を維持します。
